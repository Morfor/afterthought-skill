# How to write a solution file
- One file = one problem and the method that worked. Max 200 words, no filler.
- Path says what's inside: `topic/subtopic/[project]/what-it-solves.md`. A project folder only for project-specific commands; general knowledge sits higher.
- First line is the badge:
  `Complexity: low|high|very high · Accuracy: tested|partly tested|untested · Best: confirmed by Claude|afterthought|owner (YYYY-MM-DD)`
  - Complexity = token cost of the method.
  - Accuracy = how far it was proven.
  - Best = who confirmed it is the best known way. Rank: Claude < afterthought < owner. A lower rank never overwrites a higher one; add a dated line instead.
- Write rules and commands, not stories. Include the trap that made the file worth writing.
- Prefer improving an existing file over adding a near-duplicate.
- Delete this example folder once you have your own files.
